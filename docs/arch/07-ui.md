# 07 — UI duality

Both built. Rule: both UIs stay thin shells — all turn-affecting behavior lives in `src/` (loop, harness, registry, store). Never implement a chat-affecting feature in only one UI.

## TUI (`src/tui/`: `app.tsx`, `chat.tsx`, `input.tsx`, `theme.ts`)

Terminal app using OpenTUI (a terminal-rendering library) with Solid (the UI framework): `app.tsx` owns state and sending; `chat.tsx` renders message history + streaming draft; `input.tsx` is the prompt box; `theme.ts` holds the `goldenHour` color palette. Header shows `forge` + `provider · model (+status if not ok)`.
- State (Solid reactive variables): `messages/busy/streaming/input/providerId/model`. Keys: Ctrl-P cycles provider, Ctrl-M cycles model, Ctrl-C exits the app.
- `send()`: appends the user message to both the on-screen list and the session store, clears the box, calls `runChatTurn()` with the live `session.messages` array (which already includes the just-appended user message), then persists every returned message before mirroring the store into the render list (persist-then-render — hardening Wave 1); exceptions become `⚠` assistant bubbles. The local `messages()` list is only a render mirror — the store is the source of truth.

## Electron renderer (`public/index.html` + styles + renderer script)

Desktop web page (see `public/` for the entry HTML) that can only call the safe `window.forge.*` bridge (IPC map in `04-runtime.md`). On load it fetches session, models, skills, mods, and config, then renders: chat history, transparency event panel, skills toggle panel, mods panels (one per scope: global/repo/session), config editor, and Quest-tracker / Bitbucket PR-inbox preview badges.
- Streaming: `onDelta` replaces the in-progress draft bubble, `onTransparency` appends to the event view, `onDone`/`onError` finalize the turn.
- Any input starting with `/` is sent to `forge:command` (slash-command dispatch) instead of the model.

## Known divergences (owners: fix in loop/harness, not in a UI)

- TUI bypasses the harness layer: no `saveSessionMeta({model})` on turn (model restore is Electron-only), no Claude Code CLI backend, no main-mediated `/cd` persistence. Tracked in `09-audit.md#P0-1`.
- If you add provider/model switching, abort, skills, or mod toggles, implement once in `src/` and expose to both shells.
